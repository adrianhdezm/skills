# Clarification Policy

Ask only when the answer can change whether repository evidence represents current system state or which concern owns the knowledge.

Do not ask for information that can be discovered from repository context, existing planning artifacts, concern specs, documentation, or code.

If ambiguity is non-blocking, proceed with a clear assumption and record it in the concern spec's `Open Knowledge Gaps`.

If ambiguity blocks accurate state extraction, stop and ask one to three concrete questions.
