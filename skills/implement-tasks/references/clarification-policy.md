# Clarification Policy

Ask only when the answer can change scope, design, verification strategy, sequencing, risk, ownership, or the artifact's meaning.

Do not ask for information that can be discovered from repository context, existing planning artifacts, concern specs, documentation, or code.

If ambiguity is non-blocking, proceed with a clear assumption and record it in the relevant artifact or implementation notes.

If ambiguity blocks implementation quality, stop and ask one to three concrete questions. Prefer questions that name the decision being blocked and the consequence of each likely answer.
