# Clarification Policy

Ask only when the answer can change classification, placement, Product Vision impact, epic need, scope, verification strategy, sequencing, risk, ownership, or the artifact's meaning.

Do not ask for information that can be discovered from repository context, existing planning artifacts, concern specs, documentation, code, tests, logs, or issue reports.

If ambiguity is non-blocking, proceed with a clear assumption and record it in the routing decision.
